LR2 beta3 が曲リストをどう組み立てて見せるかを、リバースエンジニアリング版ソース（OpenLR2）とマニュアル・更新履歴から読み取った**仕様**。コードの表現は写していない（`spec-only-not-code`）。

- 出典の略号
  - `SM` = `参考に/OpenLR2-main/LR2/LR2_songmanage.cpp`
  - `SS` = `参考に/OpenLR2-main/LR2/Scene02_Songselect.cpp`
  - `MAIN` = `参考に/OpenLR2-main/LR2/Main.cpp`、`FU` = `En_fileutil.cpp`、`STR` = `strclass.cpp`
  - `H8` = `参考に/LR2beta3 2/help/8.html`（CP932）、`H3` = `help/3.html`、`HIST` = `参考に/LR2beta3 2/history.txt`（CP932、行番号は UTF-8 に変換した後のもの）
  - `CF` = `参考に/LR2beta3 2/LR2files/CustomFolder/`、`OPT` = `LR2files/Config/optionstr.csv`

- 選曲画面全体（スクロールの補間、スキン ID、入力）は `docs/lr2_select_spec.md` にある。ここでは**リストの中身**だけを扱う。

## 0. 結論（要点）

1. LR2 の曲リストは、DB（`song` 表と `folder` 表）に対する **SQL の問い合わせの結果**そのもの。木を前もって作ってはいない。フォルダを開くたび、閉じるたび、フィルタを変えるたびに問い合わせ直す。
2. **ルート** = `folder` 表で parent が「ROOT」の行。つまり**登録した曲フォルダのパスそのもの**（1 パス 1 バー）と、カスタムフォルダ・NEW SONG・ライバル・コースのフォルダ。
3. **フォルダ X を開くと**、まず「X の**直下のサブフォルダ**に入っている譜面」（`song.parent = X`）を探す。1 つでもあれば、それを**譜面バーとして直接並べ**、サブフォルダのバーは出さない。無ければ X の直下のサブフォルダをフォルダバーとして並べる。
   → **BMS が入っているフォルダ（曲フォルダ）は、フォルダバーとしては出ない。** その中の差分は、親フォルダを開いたときに 1 譜面 1 バーで並ぶ。
4. 差分は**譜面ごとに別のバー**。同じ曲（同じフォルダ・同じ鍵盤数）の差分は、既定のソート（OFF）では隣り合って、レベル順（INSANE は最後）に並ぶ。
5. 難易度フィルタ（1〜5）は「その難易度の譜面だけ見せる」ではない。**曲ごとに 1 つの難易度だけを見せ**、選んだ難易度以下で一番上の難易度を出す（無ければ一番下の難易度）。→ キーは**曲の中で 1 つ上の難易度へ進む**操作で、実際にはフィルタ全体を書き換える。
6. カスタムフォルダ（`.lr2folder`）は `#COMMAND` を `WHERE` に差し込む問い合わせ。中では難易度フィルタは効かない（全差分が出る）。

## 1. データの作り方（曲フォルダの読み込み）

### 1.1 2 つの表
- `folder` 表: path（主キー）, title, subtitle, category, info_a, info_b, command, type, banner, parent, date, max, adddate（SM:2756）。
- `song` 表: hash, title, subtitle, …, path（主キー）, type, **folder**, …, **parent**, level, difficulty, …, mode, … , adddate, exlevel（SM:2757）。
- `song.folder` = 譜面ファイルがあるディレクトリ（末尾区切り付き）の CRC32、`song.parent` = その 1 つ上のディレクトリの CRC32（SM:1364-1365, SM:3052-3055, STR:502-514）。
- `folder.parent` = そのフォルダの親ディレクトリのパスの CRC32。登録パス（ルート）は `CRC32("ROOT")`（SM:1991, 2009, 2016）。

### 1.2 登録パス（ルート）の登録（SM:1957-2032 `GetFolderDataFromPath`）
登録パスごとに 1 行、parent=ROOT で `folder` 表に入れる。
| 登録パスの中身 | type | title | その後 |
|---|---|---|---|
| ディレクトリで `folderinfo.txt` がある | folderinfo に `#CUSTOMFOLDER` があれば 2、無ければ 1（SM:1987-1988、#CUSTOMFOLDER は judge=2 を立てる SM:2971-2972） | folderinfo の `#TITLE` | 中を再帰検索 |
| `.lr2folder` ファイル | 2。`#COMMAND` が `__NEWSONG__` なら 3、`__RIVAL__` なら 4、`__EXPERT__`/`__NONSTOP__`/`__GRADE__` なら 6（SM:2002-2005） | `#TITLE` | — |
| folderinfo の無いディレクトリ | 1 | ディレクトリ名（SM:2015-2016） | 中を再帰検索 |

### 1.3 再帰検索（SM:1331-1428 `SearchSongsFromPath`）
ディレクトリ D の中の各項目について:
- 拡張子 `.bms/.bme/.bml/.pms`（FU:365-373）→ `song` 表に 1 行（folder=CRC(D), parent=CRC(D の親)）。
- `.lr2folder` → `folder` 表に type=2、parent=CRC(D) で 1 行（SM:1371-1384）。
- サブディレクトリ S → **BMS が入っているかどうかに関係なく** `folder` 表に 1 行（parent=CRC(D)）。folderinfo があれば type=その値・title=#TITLE、無ければ type=1・title=ディレクトリ名。そして S の中を再帰検索（SM:1387-1418）。
- つまり DB 上は「曲フォルダ」も普通のフォルダ行として存在する。**曲フォルダかどうかの区別は DB には無く、開くときの問い合わせの順番（§3）で決まる。**

### 1.4 カスタムフォルダ等をルートに足す（SM:2683-2885 `LoadLR2CustomFolder`）
起動時、ユーザーの登録パスの後ろに一時的に次を足して §1.2 で登録する（最後に数を戻す SM:2880）。
- コンフィグのカスタムフォルダ設定（ビット）に応じて: `CustomFolder/RANDOM/`(1), `favorite.lr2folder`(2), `TOP10.lr2folder`(4), `PLAYLEVEL/`(8), `CLEAR/`(0x10), `RANK/`(0x20), `ignore.lr2folder`(0x40), `INSANE01/` と `INSANE02/`(0x80)（SM:2701-2743）。
- 常に `course1.lr2folder`(COURSE) / `course2`(NONSTOP) / `course3`(段位認定)（SM:2745-2751）。
- ライバル（`LR2files/Rival/<id>.lr2folder`、最大 20）（SM:2857-2864）。
- 「タイトルのフラッシュ」時間内に追加した曲が 1 つでもあれば `newsong.lr2folder`（NEW SONG）（SM:2867-2876。H8 / HIST:548。フラッシュ 0 なら出ない H8）。曲の更新チェック後にも作り直す（SS:1516-1527）。
- 登録パスに無くなった ROOT 行は消す（SM:2785-2806）。

### 1.5 #DIFFICULTY の補完
- `#TITLE` の末尾の括弧 `(..)` `[..]` `-..-` を subtitle に分け、中の語（BEG/HYPER/ANOTHER/EX 等）から難易度を推定する（FU:287-360, SM:208-209）。
- それでも未定（-1、SM:2912 の初期値）の譜面は、同じフォルダ・同じ鍵盤数の中で**ノーツ数の少ない順**に、直前の譜面の難易度 +1 を振る。最初は 2（NORMAL）、5 になったら 4 に戻す（つまり 2,3,4,4,…）（SM:468-499）。

## 2. ルートの一覧

- 問い合わせ: `SELECT * FROM folder WHERE parent = CRC32('ROOT')`（MAIN:690, 713, 1102）。
- フォルダ行の一覧（`LoadBmsListFromDB`）は、**type の小さい順 → パス（大文字にして比較）の順**に並べる（SM:1832, SM:595-612）。ソート設定は関係ない（HIST:728「フォルダのソートは現在のソート設定に関わらずにパスソート」）。
- 結果としてルートの並びは:
  1. type 1: 登録した曲フォルダ（パス順。folderinfo で #TITLE を付けてもパス順）
  2. type 2: カスタムフォルダ（`LR2files\CustomFolder\...` のパス順。CLEAR, favorite, INSANE01, …）
  3. type 3: NEW SONG
  4. type 4: ライバル
  5. type 6: COURSE / NONSTOP / 段位認定（パス順で course1, 2, 3）
  - [?] 履歴は「トップに NEW SONG のショートカットが出現」（HIST:548）。OpenLR2 の並びでは NEW SONG はカスタムフォルダの後になる。「トップ」がルート階層の意味か、先頭の意味かは未確認。
- バーの絵（`#SRC_BAR_BODY` の番号）は type そのもの（SS:2605）。曲=0、フォルダ=1、カスタム=2、NEW SONG=3、ライバル=4、ライバルの曲=5、コースフォルダ=6、新規コース=7、コース=8、ランダムコース=9（SM:1662, 1767, 1777, 2312）。
- 登録パスの直下に BMS ファイルを置くと、その譜面の parent は「登録パスの親」になり、どの問い合わせにも引っかからないので**表示されない** [?]（コードからの推論。実機未確認）。

## 3. フォルダを開いたときの中身（最重要）

### 3.1 問い合わせの順番
フォルダバー（keymode≤0 でコースでないもの）で決定すると、次の問い合わせを**上から順に試し、最初に結果が出たもので一覧を作る**（SS:2360-2397, SS:1532-1555）。

- フォルダに command（`#COMMAND`）が無い場合（普通のフォルダ。SS:2384-2396）:
  1. `SELECT * FROM song LEFT JOIN score … WHERE parent = CRC32(このフォルダのパス)`
  2. `SELECT * FROM folder WHERE parent = CRC32(このフォルダのパス)`
- command がある場合（.lr2folder、#COMMAND 付き folderinfo。SS:2370-2383）:
  1. `SELECT * FROM song LEFT JOIN score … WHERE <command>`（難易度フィルタを切る印付き）
  2. `… WHERE parent = CRC32(パス)`（song）
  3. `SELECT * FROM folder WHERE parent = CRC32(パス)`
- どれも結果が無ければ何も起きない（フォルダに入らない。一覧もカーソルもそのまま）（SS:1555, SS:2881-2891）。

### 3.2 これが意味すること
フォルダ X の直下に
- **曲フォルダ（BMS が入ったディレクトリ）が 1 つでもある** → 1. が当たる。X の直下のすべての曲フォルダの**全差分が、譜面バーとして X の一覧に直接並ぶ**。曲フォルダ自体のバーは出ない。
- 曲フォルダが無く、分類用のサブフォルダだけ → 1. は空なので 2. が当たり、サブフォルダがフォルダバーとして並ぶ。
- **曲フォルダと分類フォルダが混ざっている** → 1. が当たるので**分類フォルダのバーは出ない**（その中の曲には辿り着けない）[?]（コードからの推論）。
- **曲フォルダの中にさらにサブフォルダ**（例 `Song/extra/b.bms`）→ b.bms の parent は `Song`。`Song` はフォルダバーとして出ないので、b.bms は**どこからも見えない** [?]（同上。ただし `Song` に BMS が 1 つも無ければ `Song` は普通のフォルダとして出て、`extra` の差分は `Song` を開いたときに並ぶ）。
- 「曲フォルダ」の判定は「そのディレクトリに BMS が直接あるか」ではなく、「**親を開いたときに parent=親 の譜面が 1 つでもあるか**」で決まる。
- 鍵盤数フィルタで全部落ちても、鍵盤数を自動で変えて譜面を出す（§5）ので、フォルダ一覧に化けることは基本的に無い。全譜面が DP/PMS で、それを無視する設定のときだけ 2. に進む（SM:2576-2589）。

### 3.3 フォルダを閉じる・入る時のカーソル
- 開いた直後: 一覧の先頭（index 0）が選択行に来る（SS:2995-3006）。
- `#MAXTRACKS 1` のフォルダ（RANDOM 等）は、開いた直後にそのまま決定画面へ進む（SS:3012-3016, HIST:870）。
- 閉じる（← / 右クリック / 鍵盤 2）: 1 つ上の階層の問い合わせを**やり直し**（このときの難易度・鍵盤数・ソートで作り直す）、さっきまで開いていたフォルダのバーにカーソルを合わせる（SS:2437-2479, SS:3021-3043）。
- 開いたフォルダの一覧はスタックに積む（最大 1000 階層、SS:3121）。前の一覧（prevList）と今の一覧を入れ替えて使う（SS:3061-3087）。

## 4. 譜面の一覧（`LoadFilteredBmsListFromDB` SM:2034-2680）

### 4.1 全体の流れ
1. 問い合わせに `ORDER BY` が無ければ `ORDER BY folder, mode, difficulty, level` を付ける（9KEYS のときは mode を省く）（SM:2104-2140）。
2. 1 行ずつ読み、鍵盤数フィルタ（§5）と無視設定を通ったものを、§4.2 の規則で一覧に足す。
3. 選んだ難易度の譜面が一覧全体に 1 つも無ければ、難易度フィルタを自動で進めて最初からやり直す（§4.3）。
4. 譜面が 1 つも無ければ鍵盤数フィルタを自動で進めてやり直す（§5）。
5. ソート（§4.4）。

### 4.2 1 譜面ずつの扱い（難易度フィルタ d）
- 除外: DP を無視する設定で 10/14 鍵（SM:2165）、9 ボタンを無視で PMS（同）、IGNORE（favorite=2）に指定した譜面（IGNORE フォルダ以外。SM:2208）。
- **同じ hash は一覧に 1 回だけ**（先に出た方が残る。ORDER BY folder なので folder の CRC が小さい方）（SM:2232-2238, HIST:131）。
- 「グループ」= 同じ folder（曲フォルダ）かつ同じ鍵盤数。ORDER BY により、グループ内は難易度の低い順に来る。
- d = 0（ALL）: グループ内の**全譜面を 1 譜面 1 バー**で足す（SM:2478-2485）。
- d = 1..5: グループの最初の譜面（＝一番低い難易度）は必ず足す。以後、
  - 今出している難易度より上で、かつ d 以下の難易度の譜面が来たら、今出している同じ難易度の譜面を全部取り下げて、その譜面に置き換える（SM:2466-2477）。
  - 今出している難易度と同じ難易度の譜面は並べて足す（同じ難易度の差分が 2 つあれば 2 バー）（SM:2478-2485）。
  - それ以外（d より上）は足さない。
  - **結果: 各曲で「d 以下で一番上の難易度」の譜面だけが出る。d 以下が無い曲は「一番下の難易度」の譜面が出る。曲が消えることは無い。**
  - 例: 曲が N/H/A を持ち d=HYPER → H。曲が A だけ持ち d=HYPER → A。曲が N/A を持ち d=HYPER → N。
- `exlevel` を含む問い合わせ（発狂フォルダ）と keymode 0 の行は、難易度に関係なく全部足す（SM:2041, SM:2435-2444）。
- 同時に、グループごとに「難易度ごとの最初の譜面のレベル・ランプ・譜面数」を数え、グループ内の全バーに持たせる（スキンのレベルバー表示と → キーで使う）（SM:2355-2433, 2492-2540, H3「⑤レベルバー: 同じフォルダに含まれている曲のレベルとクリア状態」）。これは表示していない差分も含めて数える。

### 4.3 難易度の自動切り替え
- d ≥ 1 で、鍵盤数フィルタを通った譜面の中に**難易度がちょうど d の譜面が 1 つも無い**とき、d を +1（5 の次は 0=ALL、「難度 ALL を使用しない」なら 1）して、ある難易度になるまで進め、一覧を作り直す（SM:2555-2571）。
- 変わった値は設定にも保存される（SS:2881-2885）。つまりフォルダを移ると難易度表示が勝手に変わることがある。
- カスタムフォルダの問い合わせ・`ORDER BY` を含む問い合わせでは d は 0 に固定（SM:2097-2101）。

### 4.4 ソート（SM:2642-2676、比較関数 SM:502-612, 1559-1594）
どのソートも**まず type（バーの種類）の小さい順**（曲 0 → ライバル曲 5 …）。その後:
| 内部値 | 中身 |
|---|---|
| 0 | 曲フォルダのパス（大文字）順 → 同じフォルダなら鍵盤数順 → レベル順（INSANE=難易度 5 は +100 で最後）（SM:570-593） |
| 1 | 鍵盤数 → INSANE を最後に → レベル → タイトル（SM:1559-1579）。発狂フォルダでは ★レベル（exlevel）順（SM:502-520） |
| 2 | タイトル（大文字）→ 同じなら INSANE を最後に → レベル（SM:522-545） |
| 3 | クリアランプ → タイトル（SM:1581-1594） |
| 4 | スコア率（ライバルフォルダでは自分とライバルの差）（SM:547-568） |
- ソートは 0..4 でループ（SS:2863）。既定値 0（LR2_configsave.cpp:982）。
- 表示名は OPT:7 で `OFF, TITLE, LEVEL, FOLDER, CLEAR, RANK` の 6 つ。内部値 0 が「OFF」（フォルダ順）に当たると思われるが、1 以降の名前と中身の対応が上の表と合わない [?]（OpenLR2 の書き起こしの問題の可能性。`lr2_select_spec.md` §8 にも記載）。
- ソートの比較は qsort（安定でない）。同点の順は保証されない。
- `ORDER BY` を含む問い合わせ（TOP10 など）・ランダムではソートしない（SM:2642）。

### 4.5 既定（OFF・ALL）での見え方
X を開くと、X の直下の曲フォルダが**ディレクトリ名順**に並び、各曲フォルダの差分は**レベル順（INSANE は最後）**に隣り合って並ぶ。タイトル順ではない。

## 5. 鍵盤数フィルタ（SM:2104-2140, 2208, 2576-2638, 3062-3070, HIST:1026-1034）

| 値 | 名前（OPT:6） | 通す譜面 |
|---|---|---|
| 0 | ALL KEYS | 全部 |
| 1 | SINGLE | 5/7 鍵（keymode ≤ 8） |
| 2 | 7KEYS | 7 鍵 |
| 3 | 5KEYS | 5 鍵 |
| 4 | DOUBLE | 10/14 鍵 |
| 5 | 14KEYS | 14 鍵 |
| 6 | 10KEYS | 10 鍵 |
| 7 | 9KEYS | 9 鍵（PMS） |
- 履歴では「7KEYS: 7 鍵の無い曲は 5 鍵譜面を表示」「14KEYS: 同 10 鍵」とある（HIST:1029, 1032）が、OpenLR2 のコードは 7 鍵だけ・14 鍵だけを通す [?]。
- 通る譜面が 0 なら、フィルタを次の値へ進め、通る譜面がある値でやり直す（SM:2590-2638）。
- SELECT タブの設定（H8, SM:3062-3070）: 鍵盤数 ALL/SINGLE/DOUBLE を使わない（飛ばす）、DP をすべて無視、9 ボタンをすべて無視、「7 鍵と 5 鍵が共存する曲は 5 鍵譜面を無視」（同じ曲フォルダに 5 鍵と 7 鍵があれば 5 鍵を一覧から落とす。14 と 10 も同様 SM:2179-2197）。
- 鍵盤数ボタン・鍵盤 1（パネル中）でループ 0..7（SS:2866-2867）。

## 6. 難易度フィルタの操作（→ / SELECT）

- 値: 0=ALL, 1=BEGINNER, 2=NORMAL, 3=HYPER, 4=ANOTHER, 5=INSANE（OPT:5 の表示名は ALL, EASY, STANDARD, HARD, EXPERT, ULTIMATE）。
- 難度ボタン: 0..5 でループ（SS:2858-2860）。「難度 ALL を使用しない」なら 0 を飛ばす（H8）。
- **→ キー / SELECT（beta3 の既定）**（SS:2152-2208, H8「通常は難度変更キーを押すと、フォルダ内の次の難度の譜面を表示」）。カーソルの譜面（keymode≥5）のグループ（§4.2）を見て:
  1. 同じ難易度の別の差分がまだ後ろにある → その差分へ [?]（OpenLR2 では内部値 26 を入れているだけで、カーソル合わせの処理が無効化されている SS:2186, 2932-2940）。
  2. 今の譜面より上の難易度を持っていれば、その中で一番低いもの → **フィルタ全体をその難易度にする**。
  3. どちらも無い（一番上にいる）→ 「難度 ALL を使用しない」ならその曲の一番下の難易度。そうでなければ、今 ALL なら一番下の難易度、ALL でなければ ALL（SS:2189-2198）。
  - フィルタ全体が変わるので、**同じフォルダの他の曲もいっせいに §4.2 の規則で表示が変わる**。
  - 作り直した後のカーソル: 同じファイル → 同じ曲フォルダ・同じ鍵盤数でそのグループの最初の譜面 → …の順で探す（SS:2942-2967）。つまりカーソルは同じ曲に留まる。
  - 鳴る音は `#DIFFICULTY` の SE（無ければフォルダを開く音）（SS:2978-2984）。
- 「難度変更キーの挙動を beta1 のものに戻す」（`difficultychangetype`）: → キーは**難度フィルタを 1 つ進めるだけ**（0..5 ループ、ボタンと同じ）（SS:2200-2205, H8）。
- 「7 難度フィルタを使用しない」（`disabledifficultyfilter`）: 難易度は常に ALL。全差分が並ぶ（nazo と同等 HIST:430, H8）。→ キーは鍵盤数を進める（SS:2210-2218, 2871-2874）。

## 7. カスタムフォルダ（.lr2folder）

### 7.1 ファイル形式（CF の実物、CP932）
```
#COMMAND <SQL の WHERE 句の中身、または特別な語>
#MAXTRACKS <最大件数。0=無制限。1=ランダムに 1 曲選んで即決定>
#CATEGORY <カテゴリ名>
#TITLE <バーに出る名前>
#INFORMATION_A <説明 1 行目>
#INFORMATION_B <説明 2 行目>
```
- 読み取り: `#COMMAND`→command（`#TAG` も同じ欄）、`#MAXTRACKS`→max、`#CATEGORY`→category、`#INFORMATION_A/B`→info_a/b、`#TITLE`、`#BANNER`（SM:192-226, 2969）。
- 例: `favorite = 1`、`playcount != 0 ORDER BY playcount DESC`（MAXTRACKS 10、TOP10）、`level = 1`、`clear = 3`、`exlevel=1 AND mode=7`（発狂★1）、`level>=0 AND mode=5`（MAXTRACKS 1、RANDOM）、`date < 4285440`（年代）。
- 特別な語: `__NEWSONG__`（追加日時がフラッシュ時間内の曲 SM:2080-2082）、`__RIVAL__`、`__EXPERT__` / `__NONSTOP__` / `__GRADE__`（コース一覧 SM:2049-2060）。

### 7.2 実行
- 問い合わせ = `SELECT * FROM song LEFT JOIN score ON song.hash = score.hash WHERE <COMMAND>`（SS:2373, HIST:991-994）。
- `ORDER BY` が書いてあれば、そのまま使い、LR2 側の ORDER BY もソートも付けない（SM:2097-2100, 2642）。無ければ §4.1 の ORDER BY と §4.4 のソート。
- 難易度フィルタは 0（全差分を 1 譜面 1 バー）（SS:2378 の印 → SM:2101）。鍵盤数フィルタは効く。
- MAXTRACKS = 一覧の件数の上限（読み取りを n 件で止める SM:2163）。MAXTRACKS=1 で COMMAND に `random()` が無ければ `ORDER BY random()` を付け、鍵盤数を ALL にし（SM:2091-2096）、開いた瞬間に決定（SS:3012）。
- 同じ hash の重複は出さない（§4.2）。

### 7.3 フォルダ分け・folderinfo.txt
- `CustomFolder` 配下のディレクトリ（`RANDOM/`, `PLAYLEVEL/`, `CLEAR/`, `RANK/`, `INSANE01/`, `YEAR/` …）は、ルートに登録される普通のディレクトリ。中の `folderinfo.txt` に `#CUSTOMFOLDER` があれば type 2（カスタムの絵）になる（SM:1984-1995）。
- 中の `.lr2folder` は parent=そのディレクトリの type 2 行になる（SM:1371-1384）。開くと §3.1 の 1.（song parent=…）が空なので、`.lr2folder` のバーがパス順に並ぶ。さらにサブディレクトリを掘れば何段でも入れ子にできる。
- `folderinfo.txt` は普通の曲フォルダの分類ディレクトリにも置ける: `#TITLE`（バーの名前）、`#CATEGORY`、`#INFORMATION_A/B`、`#BANNER`、`#CUSTOMFOLDER`（絵を type 2 に）、`#COMMAND`（書けばそのフォルダは §3.1 の command ありとして動く）（HIST:906, SM:1391-1404）。
- 置き場所: ルート（§2 の type 2 の並び）。`.lr2folder` を曲フォルダの中に置けば、その階層のフォルダ一覧に出る（SM:1371）。

### 7.4 フォルダランプ
- 「フォルダランプ」設定が有効なら、フォルダ一覧を作るたびに各フォルダの中身（command があれば command、無ければ song parent=…）を集計して、フォルダバーにランプを付ける（SM:1833-1858, 725-969, H8）。

## 8. スクロール・作り直し（詳細は `lr2_select_spec.md` §3.5〜3.7）
- 一覧は**循環**する。カーソルの曲 = (選択行 − BAR_CENTER + 先頭位置 + 件数×30) mod 件数（SS:541-548）。端で止まらず反対側につながる。
- フォルダを開いた直後: 先頭の要素が選択行（SS:3002）。閉じた直後: 元のフォルダのバー（SS:3024-3029）。
- フィルタやソートの変更・タグ編集などで作り直したとき: 「同じファイル」→「同じ曲フォルダ・同じ鍵盤数のグループ先頭」→（鍵盤数変更時）「同じ曲フォルダのグループ先頭」の順で元の曲を探す。見つからなければ先頭（SS:2894-2969）。
