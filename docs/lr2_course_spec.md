# LR2 コース（段位認定・エキスパート・ノンストップ）挙動仕様書（BMjoy 実装用）

対象: LR2 beta3 100201 のコース機能。コースのデータ形式、選曲画面での見え方、プレイの流れ、リザルト、スコア保存、スキン ID。加えて、LR2 には無い「難易度表の段位」を読むための beatoraja 側の JSON 形式。
目的: BMjoy で LR2 互換のコースを **仕様から** 実装するための資料。OpenLR2 のコードは写していない。振る舞いは文章・表・短い擬似式で書いている。

## 1. コースのデータ形式

### 1.1 結論: LR2 本体は「コースファイル」を読まない。コースは song.db の表にある

- 本体（LR2body.exe）がコースを読むのは **`LR2files/Database/song.db` の 3 つの表**だけ。表は種別ごとに分かれている。`[O] LR2_songmanage.cpp:2760-2763`
  - `expert(id INTEGER primary key, title TEXT, line INTEGER, hash TEXT, ir INTEGER)` … 種別 0
  - `nonstop(...)` … 種別 1（列は同じ）
  - `grade(...)` … 種別 2（列は同じ）
  - 旧版の `course(id, title, line, hash)` 表は DB の作り直しで消す（`DROP TABLE course`）。`[O] LR2_songmanage.cpp:2694, 2760`
- 列の意味

| 列 | 意味 |
|---|---|
| id | 並び順のキー。一覧は **id の大きい順**（新しく作ったものが上）。`[O] LR2_songmanage.cpp:1638`、`[L] history.txt:95-100` |
| title | コース名 |
| line | 鍵盤数（7/5/14/10/9）。作成時は 1 曲目の鍵盤数。鍵盤数フィルタはこの列で絞る。`[O] LR2_songmanage.cpp:1150-1154, 1620-1637` |
| hash | 「コースハッシュ」。§1.2 |
| ir | 1 = IR から取り込んだコース（IR 対応・**編集不可**）。0 = 自作（IR 非対応）。`[O] LR2_songmanage.cpp:1670-1671` |

### 1.2 コースハッシュの構造

32 文字ずつの塊を並べた文字列。**先頭の 1 塊はヘッダ、その後ろに各ステージの譜面 MD5（32 桁 16 進）を順に連結**したもの。

```
[ヘッダ32文字][STAGE1 の md5][STAGE2 の md5]...[STAGEn の md5]
ステージ数 = 文字数 / 32 - 1
```
`[O] LR2_songmanage.cpp:1669`

ヘッダ 32 文字の内訳（作成・更新時の書き方から読み取った。`[O] LR2_songmanage.cpp:1141-1160`）

| 位置（0 始まり） | 内容 |
|---|---|
| 0..9 | ステージ間のつなぎ方（1 桁ずつ、0..5）。位置 i は「STAGE i+1 → i+2」のつなぎ。ノンストップ以外では 0。OpenLR2 では `courseKeys[]` という名前だが中身はつなぎ方 |
| 10 | コース種別（0/1/2） |
| 11..13 | 予約（作成時は常に 0）。[?] beta2.5 にあった GAUGE / SCROLL SPEED / OPTION BAN（§1.5）の置き場だった可能性があるが、beta3 の本体は 0 を書くだけで読まない |
| 14..27 | 0 埋め |
| 28..31 | 作成者のパスワード MD5 の先頭 4 文字 |

- つなぎ方の値: 0 = FADE、1 = FADE+FIT、2 = CUT、3 = CUT+FIT、4 = BLANK1、5 = BLANK2。`[O] structure.h:1489`、`[L] history.txt:262-268`
- 作成者ごとに末尾 4 文字が変わるので、**同じ曲の並びでも作った人が違えば別のコース（別のスコア、別の IR ランキング）になる**。`[L] history.txt:93`
- **ヘッダが変わればコースハッシュが変わり、スコアは引き継がれない**（つなぎ方を変えるとスコアがリセットされる、という history の記述と一致）。`[L] history.txt:260`
- 読み込み時、ヘッダの解釈（つなぎ方・種別の取り出しと「プレイ可能」フラグの初期化）は **文字数が 64 以上（＝1 ステージ以上）のときだけ**行う。`[O] LR2_songmanage.cpp:1673-1679`
- ステージ数は最大 10 として読む（10 を超えても 10 で打ち切り）。`[O] LR2_songmanage.cpp:1672`
  - ただしプレイ側の譜面パスの置き場は 5 つしかなく、譜面読み込みもステージ数を 5 に丸める。**実際にプレイできるのは 5 ステージまで**。6 以上のコースは LR2 では正しく動かない [?]。`[O] structure.h:1487`、`[O] LR2_bmsload.cpp:2212-2213`
  - 本体のコース作成も 5 曲まで（§1.4）。

### 1.3 譜面の解決と、譜面が無いとき

一覧を作るとき（コースフォルダを開いたとき）に、各ステージの md5 を **song 表から md5 で引く**。`[O] LR2_songmanage.cpp:1681-1698`

- 見つかった: そのステージのタイトル・サブタイトル・レベル・#DIFFICULTY・総ノーツ数（その譜面の自己ベストに記録されている総ノーツ数。未プレイなら 0）を控える。
- 見つからない: そのステージのタイトルを「この曲を所持していません」、レベルを -1 にし、**コース全体を「プレイ不可」**にする。
- ステージが 0、またはプレイ不可のときは、コースバーのアーティスト欄（文字列 14/24）に「曲が設定されていないのでプレイできません」を入れる。`[O] LR2_songmanage.cpp:1699-1705`
- プレイ不可のコースで決定しても何も起きない（オートプレイ・リプレイも同じ）。`[O] Scene02_Songselect.cpp:2101, 2109, 2399`
- SHA-256 は使わない。LR2 は md5 だけで引く。

### 1.4 本体でのコース作成・編集（参考。BMjoy で入れるかは別判断）

選曲画面に組み込まれている。`[O] Scene02_Songselect.cpp:2325-2431, 2495-2520`、`[L] history.txt:240-320`

- コースフォルダを開くと、末尾に「NEW COURSE」（種別 7、アーティスト欄「新規コースを作成します」）と、段位認定フォルダ以外では「RANDOM MIX」（種別 9、「ランダムでコースを作成します」）が付く。`[O] LR2_songmanage.cpp:1761-1782`
- NEW COURSE を決定 → コース作成モード（timer 17 起動、パネル開音）。曲を決定するたびに追加（**最大 5 曲、2 曲目以降は 1 曲目と同じ鍵盤数のみ**）。右クリックで最後の 1 曲を外す。5 曲入った状態でもう一度決定すると確定（timer 18、パネル閉音）して DB に書く。作成ボタン 230 / 取消 231 もある。
- コース名は文字列 170 で編集。初期値「コースタイトルを入力して下さい」。
- 削除（ボタン 233）、名前変更、並べ替え（F3 を押しながら ↑↓ で id を入れ替え）。`[O] Main.cpp:2320-2335`、`[O] LR2_songmanage.cpp:1176-1210, 1277-1300`
- IR から取り込んだコース（ir=1）は編集・削除できない（書き込み処理が何もしない）。`[O] LR2_songmanage.cpp:1136`
- ノンストップの自作コースだけ、ボタン 240..248 でステージ間のつなぎ方（0..5）を変えられる。`[O] LR2_skinobject.cpp:3947-3963`
- RANDOM MIX は既存の「RANDOM MIX」という名前のコースを消してから、`config.xml` の `<course>` 設定（得意レベル・レベル上下限・BPM 幅・BPM 上下限・ステージ数）で曲を抽選して新規コースとして書く。ステージ数が 1..5 以外なら 2..4 のランダム。同じフォルダの曲は 2 度選ばない。`[O] LR2_songmanage.cpp:1867-1950`、`[O] LR2_configsave.cpp:507-534, 1118-1130`

### 1.5 コースの共有ファイル（.lr2crs）— 本体ではなくコンフィグプログラムが取り込む

- LR2IR のランキングページからコースファイル（`.lr2crs`、中身は XML）をダウンロードし、**コンフィグプログラム（LR2.exe）にドロップ**すると song.db に登録される。`.xml` で保存されてしまった場合もドロップで登録できる。`[L] history.txt:59, 94`
- 取り込み処理は LR2.exe 側にあり、**OpenLR2 には無い**（OpenLR2 は本体 LR2body.exe の書き起こし）。以下は `LR2.exe` の文字列からの再構成で、要素の並び・入れ子は確定していない [?]。
  - 文字列に `<?xml version="1.0" encoding="shift_jis"?>`、`courselist`、`course`、`hash`、`title`、`line` と、取り込み用の SQL（3 表それぞれに `ir=1` で挿入する文）が並ぶ。
  - 推定される形（Shift_JIS）:
    ```xml
    <?xml version="1.0" encoding="shift_jis"?>
    <courselist>
      <course>
        <title>コース名</title>
        <line>7</line>
        <hash>ヘッダ32文字 + md5 × ステージ数</hash>
      </course>
      ...
    </courselist>
    ```
  - どの表に入れるかの決め方は文字列からは分からない。hash の位置 10（種別）で振り分けると考えるのが自然だが未確認 [?]。
  - 取り込んだコースは ir=1（IR 対応・編集不可）。
- beta2.5 の history には「OUTPUT COURSE FILE（予定）」「コース別の GAUGE（GRADE/COURSE/EXPERT/100%）・SCROLL SPEED・OPTION BAN の設定」が書かれている。`[L] history.txt:256-290`。ボタン 250..252・文字列 180..182 として資料にも残っている（`[L] スキン関連ドキュメント/button.txt:384-396`、`text.txt:116-119`）が、**beta3 の本体（OpenLR2）ではゲージ・ソフラン・オプション禁止はコースごとの設定ではなく「段位認定（種別 2）なら固定で適用」**になっていて、ボタン 249..252 は実装が無い。`[O] LR2_skinobject.cpp:3965`（「249 250 251 252 not found」）。§3.4 を参照。

### 1.6 難易度表のコース

LR2 には難易度表を読む機能が無い（発狂 BMS の★表示はカスタムフォルダ INSANE01/02 でレベルを付けるだけ）。**難易度表由来のコースは LR2 には存在しない**。段位は LR2IR の .lr2crs で配られていた。BMjoy で表の段位を読むなら §6 の形式を使い、LR2 のコースに写す（§6.4）。

## 2. 選曲画面での見え方

### 2.1 フォルダ構造

- ルートに常に 3 つのカスタムフォルダが出る（ユーザー設定に関係なく登録される）。`[O] LR2_songmanage.cpp:2745-2750`、実体は `[L] LR2files/CustomFolder/course1..3.lr2folder`

| ファイル | #COMMAND | #TITLE | #INFORMATION_A / B |
|---|---|---|---|
| course1.lr2folder | `__EXPERT__` | COURSE | 複数の曲を連続してプレイするモードです |
| course2.lr2folder | `__NONSTOP__` | NONSTOP | 曲をDJMIX風につなげてプレイするモードです |
| course3.lr2folder | `__GRADE__` | 段位認定 | 腕前判定モードです / 一部のオプションは強制的に無効になります |

  （#CATEGORY はどれも「コースフォルダ」、#MAXTRACKS 0）
- これらのフォルダはバー種別 **6（コースフォルダ）**として登録される（#COMMAND が 3 つのどれかなら種別 6）。`[O] LR2_songmanage.cpp:2006`

### 2.5 決定

- プレイ可能なコースで決定 → **決定画面（decide）を 1 回だけ出す**（曲と同じ。この時点の選択バーはコースなので、決定画面の文字列 10 等はコース名、STAGEFILE は無し）。`[O] Scene02_Songselect.cpp:2427-2430`、`[O] Main.cpp:1166-1199`
- [W] WMIX_HD の decide は `#ELSEIF,290` でコース用の帯画像に切り替える。`[T] WMIX_HD/decide/decide.csv:184`
- 選曲画面を閉じるときに「コースモード」に入る（選択バーがプレイ可能なコースのとき）。`[O] Main.cpp:1520-1593`
  1. 各ステージの md5 から譜面パスを引いて控える。
  2. 種別・つなぎ方を控える。
  3. 種別 2（段位）ならプレイ設定を書き換える（§3.4）。種別 1（ノンストップ）ならピッチ変更を切る。
- コースでない通常プレイでも「ステージ数 1・現在ステージ 0」に設定される（§5.1 の op 289 に影響）。`[O] Main.cpp:1520-1527`

## 3. プレイの流れ（エキスパート・段位）

### 3.1 画面遷移

```
選曲 → 決定 → [STAGE1 プレイ] → [STAGE1 リザルト(通常リザルトスキン)]
            → [STAGE2 プレイ] → [STAGE2 リザルト] → … → [最終ステージ リザルト] → コースリザルト → 選曲
```

- **2 ステージ目以降は決定画面を出さない**。リザルトから直接プレイへ行き、プレイスキンの読み込み演出（LOADING）だけ出る。`[O] Main.cpp:1853-1861`
- 各ステージは**その都度、譜面を 1 曲ずつ読み込む**（エキスパート系）。ノンストップは全ステージを最初に一括で読む（§3.7）。`[O] LR2_bmsload.cpp:2238-2280`
- ステージのリザルトを抜けるときの分岐（`[O] Main.cpp:1853-1861`）:

```
リザルト終了時:
  ゲージ種別を「記録用に一時変更していたもの」から戻す（[EXT] GAS 関連）
  もし 次のステージがある
       かつ 今回のクリア種別が 0 でない（＝スコア保存処理を通った）
       かつ (BATTLE なら 2P も同様)
       かつ 1P の現在ゲージ HP ≥ 2.0
     → ステージ番号 +1、プレイへ
  そうでなければ → コースリザルトへ
```

  - 「生きていて次がある」なら進む。**閉店（HP < 2%）した時点で残りのステージは遊ばずにコースリザルトへ**行く。
  - 最終ステージを終えた場合も同じ分岐でコースリザルトへ。
- オートプレイのときは**ステージのリザルトを出さず**、プレイ → 次のプレイへ直接進む。最後だけコースリザルト。`[O] Main.cpp:1830-1833`

### 3.2 途中でやめたとき

- プレイ中の ESC 等（ESC 長押し / START+SELECT 長押し / マウス右長押し）→ フェードアウト → プレイを閉じる。`[O] Scene04_Play.cpp:1197-1206, 1213-1217`
- プレイを閉じるとき（`[O] Main.cpp:1708-1736`）:
  - 1 ノーツも処理していない → **選曲へ戻る（コース放棄。リザルトもコースリザルトも出さない）**。
  - GOOD 以上の判定が 1 つ以上ある → スコア保存処理 → ステージのリザルト。
  - それ以外（BD/POOR しか無い）→ 選曲へ戻る。
- 曲の途中で抜けた場合、未処理のノーツが残っていれば**全ゲージの HP を 0 にして**から終える（＝不合格扱い）。`[O] Scene04_Play.cpp:1659-1664`
- よって「途中でやめる → そのステージのリザルト（FAILED）→ コースリザルト（FAILED）」になる。

### 3.3 ステージ間で引き継ぐもの・引き継がないもの

プレイ開始時の初期化で、**ステージ番号が 1 以上なら以下を前のステージから持ち越す**。`[O] LR2_bmsload.cpp:537-571`

| 持ち越す | 中身 |
|---|---|
| 全 6 ゲージの HP | GROOVE〜G-ATTACK すべて。つまり **ゲージは前ステージの終わりの値から始まる** |
| 現在ゲージ種別 | |
| コース通しのコンボ / 最大コンボ | `now_combo_course` / `max_combo_course`。判定のたびに通常のコンボと並行して数える。`[O] Scene04_Play.cpp:207-222` |
| コース通しの判定数 | PG/GR/GD/BD/POOR の累計（`judgecount2`） |
| コース通しの処理済みノーツ数 | `note_current2` |
| コース通しの総ノーツ数 | `total_note`。各ステージ読み込みの最後にそのステージの総ノーツ数を足す。`[O] LR2_bmsload.cpp:4085-4087` |
| 表示中コンボ値 | 画面のコンボ表示はコース通しの値（§5.1） |
| （[EXT] FAST/SLOW 累計など） | |

| 引き継がない（ステージごとに 0 から） | |
|---|---|
| そのステージの判定数・スコア・EX スコア・レート・コンボ・最大コンボ | 通常のリザルトに出る値 |
| ゲージ推移グラフ | ステージごとに作り直す |
| 総ノーツ数（`totalnotes`） | そのステージの値 |

- STAGE1 の開始時だけ HP を初期化する: 通常プレイは GROOVE/EASY = 20%、**コースでは GROOVE/EASY も 100% から始まる**。HARD 系は 100%。`[O] LR2_bmsload.cpp:575-597`
- ハイスピード・レーンカバー等: コース専用の処理は見当たらない。プレイ設定の値をそのまま使うので、**前のステージで変えた値がそのまま次に残る**（通常プレイで次の曲に残るのと同じ）[?]。
- 乱数（RANDOM 等の配置）: ステージごとに新しく決まる（選曲を閉じるときに種を 0 にし、各ステージは新規読み込み）。`[O] Main.cpp:1522`

### 3.4 ゲージとオプション

**(1) ゲージの増減（コース中）** `[O] LR2_bmsload.cpp:3879-4007`

コースでは**ゲージの増減量の表そのものが通常プレイと違う**。通常の GROOVE/EASY は TOTAL とノーツ数から回復量を出すが、コースでは固定値。

段位認定（種別 2）

| ゲージ | PG | GR | GD | BD | POOR | 空POOR |
|---|---|---|---|---|---|---|
| GROOVE | +0.1 | +0.1 | +0.04 | -2.0 | -3.0 | -2.0 |
| HARD | +0.1 | +0.1 | +0.04 | 通常と同じ（ノーツ数基準の値 ×6） | 同 ×10 | 同 ×2 |
| DEATH | 0 | 0 | 0 | -100 | -100 | 0 |
| EASY | GROOVE と同じ | | | | | |
| P-ATTACK | +0.1 | -1.0 | -100 | -100 | -100 | -100 |
| G-ATTACK | 通常と同じ | | | | | |

エキスパート・ノンストップ（種別 0/1）

| ゲージ | PG | GR | GD | BD | POOR | 空POOR |
|---|---|---|---|---|---|---|
| GROOVE | +0.1 | +0.1 | +0.04 | -1.5 | -2.0 | -1.5 |
| HARD | +0.1 | +0.1 | +0.05 | 通常と同じ | | |
| DEATH / P-ATTACK / G-ATTACK | 通常と同じ | | | | | |
| EASY | +0.12 | +0.12 | +0.048 | -1.2 | -1.6 | -1.2 |

（HARD の「通常と同じ」は、ノーツ数と TOTAL から出す係数 × 6/10/2 の減少。値の式は通常プレイの仕様書側で扱う。段位の HARD は GD の回復だけ 0.04 に変わる。）

**(2) 判定ごとの HP 計算の違い** `[O] Scene04_Play.cpp:160-180`

```
各ゲージ g について:
  hp = 現在値を偶数に切り捨てたもの
  減少判定（BD/POOR/空POOR）かつ hp ≤ 30 かつ
      （g が GROOVE/EASY 以外 または コース中） → 変化量 × 0.6（減りが 4 割軽くなる）
  HP += 変化量
  コースでない かつ g が GROOVE/EASY かつ HP ≤ 2 → HP = 2（通常は 2% で止まる）
  100 で頭打ち、0 未満は 0
  元の hp ≤ 0 なら HP = 0 のまま（死んだゲージは生き返らない）
```

- **コース中は GROOVE/EASY も「30% 以下で減り 0.6 倍」が効き、2% の下限が無い**（0 まで落ちる）。
- 地雷の HP 計算（`[O] Scene04_Play.cpp:262-279`）はコースでも 2% 下限が残る（コース判定が無い）[?]。

**(3) 閉店（途中終了）** `[O] Scene04_Play.cpp:1595-1605`

- 現在ゲージの HP < 2.0 で閉店（timer 3、閉店音）。これはゲージ種別に関係なく判定しているので、**コースでは GROOVE/EASY でも HP が 2% を割れば閉店する**（通常プレイでは GROOVE/EASY は 2% で止まるので閉店しない）。
- つまりコースの GROOVE/EASY は実質「回復の遅い生存ゲージ」。

**(4) ゲージ表示** `[O] Scene04_Play.cpp:721-731`、`[O] LR2_skinobject.cpp:152-167`

- プレイ画面のゲージ描画: 通常プレイの GROOVE/EASY だけ「ノーマル（80% 境界のある）」表示。**コース中は GROOVE/EASY も赤ゲージ（サバイバル）表示**。
- op 42/44（1P/2P ノーマル系ゲージ）はコース中は偽、op 43/45（赤ゲージ）はコース中は真。資料にも「スキンオプション 42-45 でコース系の場合は強制的に 42、44 オフ、43、45 オン」とある。`[L] skin_history.txt:8`
- リザルトのゲージグラフも、コース中は GROOVE/EASY を 80% 境界で色分けしない。`[O] Scene05_Result.cpp:53, 73, 97, 117`

**(5) 段位認定のオプション制限** `[O] Main.cpp:1546-1588`、`[L] history.txt:92`、`[L] CustomFolder/course3.lr2folder`

段位（種別 2）を始めるとき、プレイ設定を次のように**書き換える**:

| 項目 | 段位での扱い |
|---|---|
| RANDOM 系（1P/2P とも） | OFF（正規）。**MIRROR も不可** |
| ゲージ | EASY → GROOVE、G-ATTACK → GROOVE。GROOVE / HARD / DEATH / P-ATTACK はそのまま使える |
| EFFECT（HIDDEN / SUDDEN / HID+SUD） | OFF |
| ASSIST（オートスクラッチ等） | OFF |
| BATTLE 系 | OFF |
| EXTRA MODE、DP FLIP、各種マニアックオプション、オートキー | OFF |
| ピッチ変更 | OFF |

- この書き換えはコース後に**元に戻す処理が見当たらない**（コースを遊ぶと設定が変わったまま残る）[?]。BMjoy では「コース中だけ上書きして、終わったら戻す」にするか要判断。戻さないのが LR2 と同じ。
- エキスパート・ノンストップは制限なし（ただしノンストップはピッチ変更 OFF、§3.7）。
- ハイスピードは段位でも制限しない。

**(6) クリア判定（ステージ単位）** `[O] LR2_statplay.cpp:163-192`

```
クリア種別 = 1 (FAILED)
全ノーツをコンボでつないだ → 5 (FULLCOMBO)
ゲージが HARD / G-ATTACK / P-ATTACK:
   全ノーツ処理済み かつ HP ≥ 2 → 4 (HARD)
それ以外（GROOVE / EASY / DEATH）:
   コース中: 全ノーツ処理済み かつ HP ≥ 2 → EASY なら 2、他は 3 (NORMAL)
   通常:     全ノーツ処理済み かつ HP ≥ 80 → 同上
```

- コース中の GROOVE は「2% 以上残っていればクリア」。
- [?] DEATH は HARD 側の分岐に入っておらず、GROOVE と同じ扱い（クリアで 3）になる。書き起こしの通りだが、原典の意図かは不明。

### 3.5 ステージのリザルトで保存するもの（各譜面のスコア）

エキスパート系では、**ステージごとにその譜面自身のスコアも更新する**。`[O] LR2_statplay.cpp:596-711`

- 保存しない条件（その場合もコースは続く）: オートプレイ、BATTLE（G-BATTLE 以外）、EXTRA、各種マニアック、オートキー、ASSIST、SCATTER 以上の乱数（S-RANDOM は保存する）、HS 固定 CONSTANT。`[O] LR2_statplay.cpp:7-23`
- 更新する項目:
  - EX スコアが自己ベストを超えたら判定内訳・スコア・レート・ランク・乱数種・使用オプションを更新し、ゴーストも書く。
  - 最大コンボ（そのステージ内の値）・最小 BP（未処理ノーツは BP に数える）を良ければ更新。
  - 全ノーツ処理済みなら「完走」フラグ。
  - オプション履歴に今回の分を足す。
  - **ランプは FULLCOMBO のときだけ 5 に上げる。それ以外のクリアランプはコース中のプレイでは付かない**。
  - **プレイ回数・クリア回数・失敗回数は増やさない**。
- IR 送信: 単体で 1 回もプレイしていない譜面（プレイ回数 0）は送らない（「単体でプレイしたことの無い曲はIRに登録されません」）。

### 3.6 リトライ

- ステージのリザルト・コースリザルトの終わりで、白鍵と黒鍵を同時に押していると**コースの最初（STAGE1）からやり直し**になる（2 ステージ目以降からは「同じ譜面をもう一度」にはならない）。`[O] Scene05_Result.cpp:211-223, 300-324`
  - ただしこの「リザルトでのリトライ」の入口は OpenLR2 で整理された処理の一部で、プレイ中の Quick Restart は [EXT]。原典 LR2 のリザルトからのリトライがコースでどう動くかは未確認 [?]。

### 3.7 ノンストップ（種別 1）

- 全ステージ（最大 5）を**最初に 1 本の譜面として連結して読む**。ステージの切れ目に内部の印を入れ、そこを通過すると現在ステージ番号が進み、文字列 10 がそのステージのタイトルに変わる。`[O] LR2_bmsload.cpp:2250-2276`、`[O] Scene04_Play.cpp:1558-1569`
- つなぎ方: FADE（5 秒のクロスフェード）、FADE+FIT（BPM を前の曲に合わせてピッチを変える）、CUT（200ms で切り替え）、CUT+FIT、BLANK1（少し間を空ける）、BLANK2（約 5 秒空けて次の曲を頭から）。`[O] LR2_bmsload.cpp:3128-3145, 3271-3297`、`[L] history.txt:262-268`
- スクロールは BPM 変化を無視した一定速度（HS 固定 CONSTANT 相当）で、速度倍率は 1.0 に固定。`[O] LR2_bmsload.cpp:2717, 3314`
- 2 ステージ目以降は 1 ステージ目と同じ鍵盤数のみ（作成時に制限）。
- **コース全体を 1 曲として扱う**。スコアはコースハッシュで通常の保存処理に入り、各譜面のスコアは保存しない。リザルトは通常のリザルト 1 回だけで、**コースリザルトは出ない**（リザルト後は選曲へ）。`[L] history.txt:249-252`、`[O] Main.cpp:1853`（種別 0/2 だけを扱う）
- BGA はステージごとに層を持ち切り替える。
- OpenLR2 の既知の問題に「NONSTOP MIX のスコア保存の不具合」がある（`[O] ../README.md:69`）。BMjoy で入れるなら後回しでよい。

**コースのクリア種別** `[O] LR2_statplay.cpp:249-273`

## 6. 難易度表 JSON の段位（beatoraja が読む形式）

LR2 には無い機能。BMjoy で発狂 BMS・Satellite 等の段位を読むための形式。beatoraja は難易度表の解析を `jbmstable-parser` に任せている。

### 6.1 ヘッダ JSON（header.json）の `course`

`[J] decodeJSONTableHeader`、`[B] src/bms/player/beatoraja/TableDataAccessor.java:191-211`

- ヘッダに `course` キーがあれば読む。値は次の 2 つの形を受け付ける:
  - **配列の配列**: `[[コース, コース, ...], [コース, ...]]` … グループごとの段位セット（例: 通常段位と発狂段位を別グループに）。
  - **コースの配列**: `[コース, コース, ...]` … 1 グループとして扱う。
  - 判定は「先頭の要素が配列か、オブジェクトか」。
- beatoraja は全グループを平らに 1 列にして使う（グループの区切りは捨てる）。
- コース 1 件の形:

```json
{
  "name": "発狂初段",
  "charts": [
    { "md5": "0123...", "sha256": "abcd...", "title": "曲名", "artist": "...", ... },
    ...
  ],
  "constraint": ["grade_mirror", "gauge_lr2", "ln"],
  "trophy": [
    { "name": "goldmedal",   "missrate": 1.0, "scorerate": 90.0 },
    { "name": "silvermedal", "missrate": 3.0, "scorerate": 85.0 },
    { "name": "bronzemedal", "missrate": 5.0, "scorerate": 80.0 }
  ],
  "style": "..."
}
```

| キー | 型 | 意味 |
|---|---|---|
| name | 文字列 | コース名。無ければ beatoraja は「No Course Title」（`[B] CourseData.java:103-105`） |
| charts | オブジェクトの配列 | 各ステージの譜面。中身は難易度表データの 1 曲分と同じキー（`md5`, `sha256`, `title`, `artist`, `url`, `url_diff`, `mode`, `org_md5` など）。**md5 / sha256 のどちらか**で譜面を特定する。beatoraja は小文字にそろえる（`[B] TableDataAccessor.java:226-231`） |
| md5 | 文字列の配列 | 旧形式。`charts` が無いときだけ、md5 の配列として読む |
| constraint | 文字列の配列 | 制約（§6.2）。**jbmstable-parser は無いと例外で表全体の読み込みに失敗する**（null チェックをしていない）。BMjoy は「無ければ空」と扱えばよい |
| trophy | 配列（任意） | トロフィー条件。`name`, `missrate`（%）, `scorerate`（%）, `style`。beatoraja 本体はコースエディタで作るだけで、判定には使っていない（skin 用）。`[B] launcher/CourseEditorView.java:163-166` |
| style | 文字列（任意） | 表示用。beatoraja は使っていない |

- 旧形式 `grade` キー（`course` が無いときだけ）: `[{ "name": ..., "md5": [...], "style": ... }]`。制約は指定できず、**常に `["grade_mirror", "gauge_lr2"]` として読む**。`[J]`（バイトコードのオフセット 832-1090）
- ヘッダの必須は `name` と `symbol`（無ければ「ヘッダ部の情報が不足しています」）。`course` は任意。

### 6.2 constraint の名前と意味（beatoraja の解釈）

`[B] CourseData.java:146-202`（名前と分類）、適用は `[B] select/MusicSelector.java:476-507`、`play/BMSPlayer.java:419-424, 833-838`、`play/LaneRenderer.java:95-103`、`play/JudgeManager.java:175-184`、`play/GrooveGauge.java:125-147`

| 名前 | 分類 | 意味（仕様として） |
|---|---|---|
| `grade` | 段位 | 段位コース。乱数は正規のみ（RANDOM / MIRROR とも不可、DP のオプションも OFF） |
| `grade_mirror` | 段位 | 段位コース。正規か MIRROR だけ可（MIRROR を選んでいれば 2P 側も MIRROR に合わせる。それ以外の乱数は正規に戻す） |
| `grade_random` | 段位 | 段位コース。RANDOM 系も可（ただし beatoraja の乱数番号 6 以上＝S-RANDOM 系などは正規に戻す） |
| `no_speed` | ハイスピード | ハイスピード変更禁止。HS = 1.0、レーンカバー・LIFT・HIDDEN = 0、HS 固定の一部（Constant）無効。プレイ中の HS 操作も無効で、設定は保存しない |
| `no_good` | 判定 | GOOD 判定を無くす（GOOD の窓を 0 にする） |
| `no_great` | 判定 | GREAT と GOOD を無くす（PG か BAD 以下だけ） |
| `gauge_lr2` | ゲージ | LR2 式のゲージを使う |
| `gauge_5k` / `gauge_7k` / `gauge_9k` / `gauge_24k` | ゲージ | 5 鍵 / 7 鍵 / PMS / 24 鍵 の各ゲージ方式を使う |
| `ln` / `cn` / `hcn` | LN | ロングノーツの種類を LN / CN / HCN に固定 |

- 分類（段位・HS・判定・ゲージ・LN）ごとに 1 つだけ有効。同じ分類が複数あれば**先に書いたもの**を採る。知らない名前は捨てる。`[B] CourseData.java:120-127`、`[B] TableDataAccessor.java:198-199`
- `grade` / `grade_mirror` / `grade_random` のどれかがあれば beatoraja は「段位コース」扱い（`isClassCourse`）。`[B] CourseData.java:84-91`
- 譜面が 1 つでも見つからないコースは遊べない（beatoraja も同じ）。

### 6.3 実際の表

- 発狂 BMS 難易度表・Satellite・Stella などのヘッダは `course` を「配列の配列」で持ち、制約は多くが `grade_mirror` + `gauge_lr2`（+ LN 系）[?]（手元に表の実物は無いので、ここは一般的な形の記述。読み込みは §6.1 の両形に対応しておけば足りる）。

### 6.4 LR2 のコースへの写し方（BMjoy 設計上の判断。LR2 との違いの指摘）

LR2 に無い機能なので「LR2 の挙動を保つ」の範囲外。写すときに LR2 と食い違う点を挙げておく。

| 表の constraint | LR2 で近いもの | 食い違い |
|---|---|---|
| `grade*` あり | 種別 2（段位認定） | LR2 の段位は **MIRROR も不可**。`grade_mirror` を通すなら LR2 より緩い |
| `grade*` なし | 種別 0（エキスパート） | |
| `gauge_lr2` | LR2 の段位ゲージ（§3.4 の表）がそのまま当たる | LR2 にはこれ以外のゲージ方式が無い。`gauge_7k` 等は LR2 では表現できない |
| `no_speed` / `no_good` / `no_great` | 無し | LR2 の段位は HS を縛らない。判定を消す機能も無い |
| `ln` / `cn` / `hcn` | 無し | LR2 は LN（終端判定なし）だけ |

- コースハッシュ: LR2 形式のヘッダ（種別・つなぎ方・作成者 4 文字）を表のコースにも作るなら、**作成者部分をどうするか**決める必要がある（LR2IR のスコアと突き合わせる予定が無ければ、表の URL とコース名から作る等の独自規則でよい）。md5 が無く sha256 だけの譜面は LR2 形式のハッシュに入れられない。
- 段位を「難易度表フォルダの中のコースバー（種別 8）」として出すか、LR2 と同じく「段位認定」フォルダ（種別 6）にまとめるかは選曲設計の判断（memory: 選曲は難易度表中心）。

## 7. スコアの保存（コース）

### 7.1 保存先

- プレイヤーごとのスコア DB `LR2files/Database/Score/<プレイヤーID>.db` の **score 表**（曲と同じ表）に、**キー = コースハッシュ（ヘッダ + md5 連結）**で 1 行。`[O] Scene13_Courseresult.cpp:96`、`[L] LR2.exe` の文字列（score 表の定義）
- 列は曲と同じ: `hash, clear, perfect, great, good, bad, poor, totalnotes, maxcombo, minbp, playcount, clearcount, failcount, rank, rate, clear_db, op_history, scorehash, ghost, clear_sd, clear_ex, op_best, rseed, complete`。
- コースの行の ghost は空（IR にもゴースト無し "Z" で送る）。
- player 表の `grade_7` / `grade_5` / `grade_14` / `grade_10` / `grade_9`（段位）列は、OpenLR2 の範囲ではコースのクリアで更新されない（読み書きで値を素通しするだけ）[?]。`[O] LR2_statlong.cpp:15-24`

### 7.2 更新規則（コースリザルトに入ったとき） `[O] Scene13_Courseresult.cpp:4-96`

- 保存しない: オートプレイ、リプレイ再生、保存禁止状態。
  - [?] 曲単位で見ている「保存しない条件」（§3.5 の SCATTER 等）はコースの行には効いていない。段位ではそもそも乱数が OFF になるので問題にならないが、エキスパートでは SCATTER でもコースの記録が残る。
- プレイヤー統計: プレイ回数 +1、クリア（種別 2 以上）なら clear +1、でなければ fail +1、プレイ時間を加算。
- クリアランプ: **今回のコースのクリア種別（§4.2）が保存値より上なら上書き**（下がらない）。
- EX スコアが保存値を超えたら: 総ノーツ・判定内訳・スコア・EX・レート・ランク・乱数種・使用オプション（ゲージ + 乱数 ×10、DP は 2P 側と FLIP も）を更新。
- 最大コンボ（コース通し）: 大きければ更新。
- 最小 BP: 全ノーツ処理済みなら BD+POOR、途中で終わったなら BD+POOR+未処理ノーツ数。小さければ更新。
- プレイ回数 +1、クリアならクリア回数 +1、でなければ失敗回数 +1。
- オプション履歴に今回の分を足す。完走フラグ。
- IR: IR 対応コース（ir=1）でオンラインなら送る。非対応なら「このコースはIRに対応していません。」。

### 7.3 ランプ規則のまとめ

| ランプ | 条件 |
|---|---|
| FAILED | 途中で閉店・途中終了・最終ステージを生きて終えなかった |
| EASY / NORMAL / HARD | 最終ステージを HP > 2% で終えた。ゲージ種別で決まる（EASY は段位では使えない） |
| FULLCOMBO | 全ステージを通して 1 本のコンボでつないだ（コース全体の FC） |

- 「全ステージのクリア」が必要なのではなく、「生きて最後まで遊ぶ」ことが必要（途中で死ねば以後は遊べないので結果的に同じ）。
- 各譜面のランプは、コース中のプレイでは FC のときだけ上がる（§3.5）。
