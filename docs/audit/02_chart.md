# 監査 02：譜面の読み込み（BMS の解析とリソースの読み込み）

対象：BMjoy の BMS 読み込みを、OpenLR2（LR2 を逆アセンブルして作り直したもの）の挙動と突き合わせた。コードは写さず、挙動だけを書く。

- LR2 側：`参考に/OpenLR2-main/LR2/` の `LR2_bmsload.cpp`（以下 bmsload）、`LR2_songmanage.cpp`（以下 songmanage。選曲用のメタデータ ParseBMSMETA）、`En_fileutil.cpp`（以下 fileutil）、`structure.h`、`Scene04_Play.cpp`（以下 Play）、`dep/DxLib/DxSystem.cpp`
- BMjoy 側：`src/chart/bms_parser.cpp`（以下 parser）、`src/chart/chart.cpp`、`src/chart/chart_loader.cpp`、`src/util/{text,path}.cpp`、`src/util/lr2_random.h`、`src/audio/sound_bank.cpp`、`src/app/play_session.cpp`（以下 session）、`src/db/song_db.cpp`（以下 songdb）、`tests/test_bms_parser.cpp`
- 記号：[?] = 確かでない／元の LR2 と OpenLR2 で違うかもしれない。[EXT] = OpenLR2 が足した拡張で、元の LR2 には無いと思われるもの。
- 判定の欄：同じ／違う／BMjoyに無い／意図した違い（＝「BMjoy の意図した違い」。仕様書 v0.1 や bmson・osu のインポーターによるもの）／LR2に無い

LR2 は「演奏用の読み込み（bmsload の ParseBmsFile）」と「選曲用のメタデータの読み込み（songmanage の ParseBMSMETA）」を別々に持っていて、両者は同じヘッダーでも扱いが違う。BMjoy は 1 本のパーサーの結果を両方に使っている。この違いが、選曲側のずれの多くの原因になっている（6 章）。

## BMjoy に無いもの

優先度は「LR2 の譜面で、遊んだときの結果が変わるか」で付けた。

1. **高：5 鍵の判定**。18・19 が無い譜面を LR2 は 5 鍵として扱い、RANDOM・MIRROR・S-RANDOM を鍵盤 1〜5 に閉じる。BMjoy はいつも 7 鍵として並べ替えるので、5 鍵の譜面に RANDOM をかけると 6・7 鍵にノーツが来て、LR2 とは別の譜面になる（同じシードのリプレイも合わない）。選曲の鍵盤数の絞り込み（beatoraja に合わせる方針）にも 5/7 の区別が要る（songmanage:3003-3018, bmsload:3333-3480）。
2. **中：選曲用の題名と副題の分割**（fileutil:287-367）。LR2 の選曲画面では「Song [ANOTHER]」は題名「Song」と副題「[ANOTHER]」に分かれて出る。BMjoy は題名にそのまま残る。
3. **中：キー音の置き換え先の不足**。.flac・.mp3 への置き換え、1 つ上のフォルダでの拡張子の置き換え、2 段以上下のフォルダの名前が無い（fileutil:734-826 / session:47-63, path.cpp:32-35）。flac の読み込み自体も無い（.flac への置き換えは [EXT?]）。
4. **中（仕様書との関係で）：`#SCROLL`／`SC` チャンネル**。OpenLR2 の拡張 [EXT] だが、仕様書 238 行目は BMS の `#SCROLL` に対応すると書いている。
5. **低：オートプレイで、キー音の鳴り終わり・最後の BGA まで曲の終わりを延ばす処理**（bmsload:812-850）。
6. **低：選曲用のメタデータの細かい項目**（`#CATEGORY`・`#INFORMATION_A/B`・`#TAG`/`#COMMAND`・`#EXLEVEL`・`#MAXTRACKS`、`#GENRE` からの難易度の推定、RANDOM・BGA の有無）。
7. **低：FREQ（音程）での BPM の補正**、長すぎるキー音・キー音の無い譜面の印（IR 用）。オプションや IR の監査で扱う。

## 違っているもの（直すべき候補）

1. **高：`#RANDOM 0`（値なし）で乱数を消費しない**（lr2_random.h:36-39 / DxSystem.cpp:1200-1209）。DxLib の GetRand は上限が負でも乱数を 1 回引く。BMjoy は引かずに 0 を返すので、そういう行がある譜面では、その後の `#RANDOM` とレーンのランダムが LR2 と全部ずれる。負の上限のときの戻り値も LR2 は負になる [?]。直すなら「常に 1 回引いて、上限＋1 を掛けて右に 32 ビットずらす」を負の値のまま行う。
2. **中：小節 0 をずらしたときの頭の空小節の長さ**（bmsload:2589-2590 / parser:221-235）。LR2 は元の小節 0 の長さを使い、BMjoy は 1.0。`#00002` と小節 0 の頭のノーツが両方ある譜面で、全体の時刻（＝BGM とノーツの関係ではなく、曲の始まりまでの待ち時間）が変わる。
3. **中：`#BPM` が無い譜面をエラーにしている**（parser:210-213 / bmsload:2427）。LR2 は拒否せず、小節 0 の頭に 03/08 があれば普通に遊べる。少なくとも「小節 0 の頭に BPM 変更がある」場合は開けるようにする。
4. **中：選曲用のノーツ数・BPM の範囲・#RANDOM の扱い**（7 章）。BMjoy の値の方が正しいが、LR2 と表示が変わる。記憶の方針（LR2 と違う挙動は勝手に入れない）からは、どちらに合わせるかを決める必要がある。少なくとも「#RANDOM は 1 番の枝で数える」は LR2 に合わせられる（今はシード 1 の乱数で選んでいる）。
5. **低：未定義の STOP（09）で時間が戻る LR2 のバグ**（bmsload:2870-2874）。BMjoy は 0 にしている。合わせるかは要相談（まれ）。
6. **低：08 で BPM 0 を参照したとき**（bmsload:2844-2868）。LR2 は時刻が無限大に飛んで事実上壊れる。BMjoy の「無視」は妥当なので、違いとして記録するだけでよい。
7. **低：2P 側の地雷（E1〜E9）や不可視（41〜49）だけがある 7 鍵譜面をエラーにしている**（parser:202-209）。LR2 の鍵盤数の判定では、E の地雷は数えないので SP の 7 鍵になる。E だけなら「捨てて SP として読む」にしてもよい。
8. **低：曲の終わりに不可視ノーツを含めている**（parser:441 / bmsload:3486, 3649）。LR2 は含めない。
9. **低：長さ 0 の LN が同じ時刻のノーツを上書きする**（parser:400-401 / bmsload:3678）。
10. **低：UTF-8 の BOM を落とさない**（parser:105）。LR2 と同じ挙動だが、UTF-8 を読むと決めている以上、1 行目が消えるのは避けたい。
11. **低：`#DIFFICULTY` と題名からの推定の優先順位、`#DIFFICULTY 0` の扱い**（songdb:196-197 / songmanage:2912, 2970）。
12. **[?]：同じ位置・同じチャンネルの重なりで、どちらが残るか**（bmsload:2574 の qsort は安定でない）。LR2 でも決まっていないので、今の「書いた順」のままでよいと思われる。
