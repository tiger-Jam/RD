## 1. LR2 の LN（BMjoy の現状）

BMjoy の `proc_long`（`BMJ/game/judge.cpp:243-320`）は OpenLR2 の `ProcLongnote`（`OLR2:930-1130`）と同じ挙動。

| 場面 | 挙動 | 出典 |
|---|---|---|
| 始点を押した | 単ノーツと同じ幅（PG/GR/GD/BD）で始点の判定を決めるが、**まだ数えない**（保持するだけ）。始点の音を鳴らす | `OLR2:959-1040`, `BMJ/game/judge.cpp:260-288` |
| 始点の見逃し | 始点の時刻から **GOOD 幅**（NORMAL で 100ms）を過ぎても押していなければ POOR を 1 つ。LN はそこで終わり | `OLR2:939-955`, `BMJ/game/judge.cpp:251-258` |
| 始点が BAD 幅で早押し | 始点は BAD として保持する（遅い側は GOOD 幅を過ぎた時点で見逃しになるので、遅い BAD は無い） | `OLR2:1023-1040` |
| 空POOR | BAD 幅より前、空POOR 幅（1000ms）の中で押すと空POOR | `OLR2:1041-1055`, `BMJ/game/judge.cpp:289-294` |
| 押し続けて終点を過ぎた | 終点の時刻を過ぎた最初の処理で、**始点の判定で 1 回だけ**数える（コンボ・ゲージ・EX もここで） | `OLR2:1063-1090`, `BMJ/game/judge.cpp:298-306` |
| 早く離した | 終点より **GOOD 幅より前**に離したら BAD（音を止める）。GOOD 幅の中で離したら始点の判定で数える | `OLR2:1092-1125`, `BMJ/game/judge.cpp:308-319` |
| 終点の判定 | 無い。離すタイミングで PG/GR などが付くことは無い | 同上 |
| 総ノーツ数 | LN 1 本 = 1 | `BMJ/chart/chart.cpp:85-90` |

- BMjoy は始点の判定を表示用イベントとして `judge + 100` で出している（`BMJ/game/judge.cpp:282-284`）。スコアには入らない。
- LR2 には `#LNMODE` も CN/HCN も無い（OpenLR2 に該当する処理が見当たらない）。
- 参考：beatoraja の「LN」モードは LR2 と違い、離したときに終端の幅で判定して、始点と終端の悪い方を採る（`JM:532-548`）。押し続けたときは始点の判定（`JM:572-578`）。早離しは BAD（`JM:538-540`）。**BMjoy の LN は LR2 の挙動のままにする前提**で、ここは比較のためだけに書いた。

## 2. CN（チャージノート）

beatoraja の挙動。LN（始点と終端）は 2 つの判定として数える。

### 2.1 判定幅

始点は通常ノーツ（皿は皿の幅）と同じ幅。終端は専用の幅を使う（`JM:185-198`, `JP:12-33`）。

元の表（µs。`{遅い側, 早い側}`。`JP:12-33`）：

| モード | 種類 | PG | GR | GD | BD |
|---|---|---|---|---|---|
| 7KEYS | 通常ノーツ | ±20000 | ±60000 | ±150000 | −280000 / +220000 |
| 7KEYS | **LN 終端（鍵盤）** | ±120000 | ±160000 | ±200000 | −280000 / +220000 |
| 7KEYS | **LN 終端（皿）** | ±130000 | ±170000 | ±210000 | −290000 / +230000 |
| 5KEYS | LN 終端（鍵盤） | ±120000 | ±150000 | ±200000 | ±250000 |
| 5KEYS | LN 終端（皿） | ±130000 | ±160000 | ±110000 [?] | ±260000 |
| PMS | LN 終端 | ±120000 | ±150000 | ±217000 | ±283000 |

- 5KEYS の皿の GD が GR より狭い（`JP:16`）。元データの誤記に見えるが、そのまま。[?]
- 空POOR(MS) の幅（7KEYS: −150000 / +500000）は終端の表には無い。終端の表の外は **POOR(4)** になる（`JP:184-189` は表を全部外れると表の長さ＝4 を返す）。
- 判定ランクによる倍率：`#RANK 0..4` → 25/50/75/100/125%（`BJ/play/BMSPlayerRule.java:61-64`, `JP:210`）。**beatoraja では #RANK 2 (NORMAL) が 75%、#RANK 3 (EASY) が 100%**。`#DEFEXRANK x` は `x × 75 / 100` %、bmson の `judge_rank` はそのまま %（既定 100）。倍率は PG〜BD にかかる（`JP:226-236`）。
- 例：7KEYS・#RANK 2 の鍵盤の LN 終端 = PG ±90ms、GR ±120ms、GD ±150ms、BD 遅 210ms / 早 165ms。
- 判定幅のカスタム（PG/GR/GD の倍率）と段位の `no_great` / `no_good` は LN 終端の幅にもかかる（`JM:169-183, 198`, `JP:168-173, 262-273`）。`no_good` は GD の幅を 0 にして、内側の幅まで広げ直すので、GD が出なくなる。
- 離しの猶予（押し直しの猶予）：`longnoteMargin`。5KEYS / 7KEYS は 0、PMS は 200ms（`JP:15, 26, 37`）。判定カスタム時は倍率がかかる（`JM:186`）。皿は `longscratchMargin`（全モード 0。`JM:188`）。

### 2.2 始点

| 場面 | 挙動 | 出典 |
|---|---|---|
| 押した（PG〜BD） | **その場で 1 つの判定として数える**（コンボ・ゲージ・EX・FAST/SLOW すべて）。始点の音を鳴らす。終端の処理待ちに入る | `JM:424, 443-452`, `JM:639-694` |
| 押した（空POOR 幅） | 空POOR。始点は消えず、処理待ちにも入らない | `JM:401-404, 444-452`, `JP:31` |
| 見逃し | 始点の時刻から **通常ノーツの BAD の遅い側**（7KEYS #RANK2 で 210ms）を過ぎたら、**始点と終端の両方を POOR**（POOR 2 つ、ゲージも 2 回）。その LN はそれで終わり | `JM:592-607` |

### 2.3 終端（離したとき）

離した時刻で `dmtime = 終端の時刻 − 離した時刻` を LN 終端の幅で判定する（`JM:493-494`）。

| 場面 | 結果 | 出典 |
|---|---|---|
| 終端の前後で、PG/GR/GD の幅で離した | その判定をすぐ数える。終端の音（あれば）を鳴らす | `JM:510-520` |
| 早く離した（終端より前）で、BD 幅 | 猶予（`longnoteMargin`）が過ぎたら **BAD**。キー音（始点の音）を消音する | `JM:511-513, 580-589` |
| 早く離した（終端より前）で、BD 幅より前 | 猶予が過ぎたら **POOR**。キー音を消音する | 同上 |
| 猶予の中で押し直した | 早離しを取り消して、LN を続ける（7KEYS は猶予 0 なので実質できない） | `JM:371-378` |
| 遅く離した（終端より後）で、BD 幅の中 | 幅どおりの判定（遅い PG/GR/GD/BD）をすぐ数える | `JM:510-520` |
| 離さずに押し続けた | 終端の時刻から **通常ノーツの BAD の遅い側**を過ぎたら終端は **POOR**（見逃し扱い）。**押し続けるだけでは終端は取れない** | `JM:615-626` |

- 早離しで終端が確定したあとは、その LN はもう触れない（終点の時刻まで押し直しても何も起きない）。
- 終端の FAST/SLOW は `dmtime ≥ 0` を FAST として数える（`JM:652`）。早離しは FAST。
- 終端の判定は通常の判定と同じ扱い：コンボ（PG/GR/GD でつながる、BD/POOR で切れる。7KEYS では空POOR は切らない。`JP:29`, `JM:660-669`）、ゲージ（`BJ/play/BMSPlayer.java:1024`）、EX（§5）。
- 音：始点を押したときに始点の音、終端の確定時に終端のノーツの音を鳴らす（`JM:424, 516, 585`）。5x/6x チャンネルの LN の終端の音は無し扱いと思われる（`jbms:Section.lambda$makeTimeLines$9` で終端の wav に −2 を入れている）[?]。早離しの BD/POOR では始点の音の音量を 0 にする（`JM:581-583`）。

## 3. HCN（ヘルチャージノート）

始点・終端の判定は CN と全く同じ（§2）。加えて、LN が流れている間ずっとゲージが増減する。

### 3.1 増減の区間

- ノーツの**始点の時刻**を過ぎたら、そのレーンの「通過中の HCN」になる。**終端の時刻**を過ぎたら外れ、増減のカウンタを 0 に戻す（`JM:233-243`）。
- ただし始点がまだ判定されていない間（始点の時刻を過ぎたが押してもいないし見逃しにもなっていない間）は増減しない（`JM:306-311`）。始点を見逃して POOR が付いたあとは増減の対象になる。

### 3.2 押しているかの判定と増減

- 「増やす側」になる条件（`JM:288-293`）：
  - そのレーンのキーを押している、または
  - 終端がもう PG/GR/GD で判定済み（GD 幅の中で早めに離した場合など）、または
  - オートプレイ。
- それ以外は「減らす側」。
- 増減はヒステリシス付きのカウンタで決める（`JM:313-337`）：
  - 増やす側の間は経過時間を足し、**200ms を超えるたびに** `GREAT の増加量 × 0.5` をゲージに加えて 200ms 引く。
  - 減らす側の間は経過時間を引き、**−200ms を下回るたびに** `BAD の減少量 × 0.5` を加えて 200ms 足す。
  - 間隔は定数 `200000 µs`（`JM:81`）。
  - 例：押していてカウンタが +150ms のときに離すと、最初の減少は 350ms 後。
- ゲージの増減量は全ゲージに、そのゲージの GREAT / BAD の値 × 0.5 で入る（`GG:57-61, 229-240`）。減少には guts（残量が少ないと減りが緩む表）がかかる（`GG:231-237`）。GROOVE 系の増加量は `TOTAL / 総ノーツ数` で決まる（`GG:260`）ので、HCN の増加も総ノーツ数（CN 扱いの 2 倍の数え方）に依存する。
- **増減は判定ではない**：判定数・コンボ・EX・FAST/SLOW・処理済みノーツ数のどれにも入らない（`updateMicro` を通らない。`JM:316, 328`）。
- スキン用に「HCN 増加中」「HCN 減少中」のタイマーを入れ替える（`JM:320-321, 332-333, 882-883`）。
- 音：終端が BD/POOR で確定したあと（早離しのあと）は、押し直すと始点の音の音量を戻し、離すと 0 にする（`JM:322-324, 334-336`）。押し直しの発音は未決とソースに TODO がある（`JM:26`）。
- 注意：beatoraja はフレームごとに「そのフレームの頭で押していたか」を見て、フレーム間の経過時間をまとめて足し引きしている（`JM:219-229, 314, 326`）。入力の時刻では区切っていない。BMjoy で入力の時刻から決定的に計算すると、フレーム 1 つ分ほどずれうる [?]。

### 3.3 終端

CN と同じ（§2.3）。早離しで終端が BD/POOR になっても、終端の時刻までは増減が続く（押し直せば増える）。

## 4. 皿の BSS（バックスピンスクラッチ）— 任意

皿のレーンの CN/HCN だけの挙動（beatoraja）。皿のレーンには上回し・下回しの 2 つのキーがある。

- 始点を押したキーを覚える（`JM:448-450`）。
- 押している間に**同じキーを離しても**、離しの判定が POOR（終端の幅より前）のときだけ早離しとして扱う。それ以外の離しは無視する（`JM:502-509`）。回している途中でキーが切れても LN は切れない。
- **反対向きのキーを押した瞬間**を終端の判定にする（皿の LN 終端の幅。`JM:359-370`）。
- 反対に回さずに終端を過ぎたら、終端は POOR（`JM:615-626`）。
- LN モード（beatoraja の LN）の皿は、始点を押したキーを離したときだけ離しとして扱う（`JM:523-531`）。
- LR2 に BSS は無い。BMjoy の入力が皿を 1 レーン 1 状態として扱っているなら、BSS には「どちら向きか」を判定エンジンまで通す必要がある。

## 5. 総ノーツ数・判定数・最大 EX

| モード | LN 1 本の数え方 | 判定の回数 | 出典 |
|---|---|---|---|
| LN | 1 | 1（LR2：終点か離したときに始点の判定で） | `jbms:BMSModelUtils.getTotalNotes@395-436` |
| CN | 2 | 2（始点・終端） | 同上 |
| HCN | 2 | 2（始点・終端。増減は数えない） | 同上 |

- 数え方（`jbms:BMSModelUtils.getTotalNotes@395-436`）：LN の始点は常に 1。終端は「ノーツの種類が CN/HCN」または「種類が未定義でプレイヤーの設定が LN 以外」のときだけ 1。
- EX スコア = `(PG の数) × 2 + (GR の数)`（`BJ/ScoreData.java:405-406`）。終端の判定も同じく入る。**最大 EX = 総ノーツ数 × 2**（CN/HCN では LN 1 本ぶんが 4 点）。
- 処理済みノーツ数（`passnotes`）は判定が出るたびに 1 増える（`JM:640-647`）。CN の見逃しは 2 増える。フルコンボの判定は「処理済み = 総ノーツ数 = コンボ」（`BJ/play/BMSPlayer.java:1028-1029`）。
- ゲージの増加量（GROOVE 系）は `TOTAL / 総ノーツ数` なので、CN では LN の多い譜面ほど 1 判定あたりの回復が小さくなる（`GG:260`）。
- 曲 DB に入れる総ノーツ数は、beatoraja は LN の設定で読み込んで数えている（`BJ/song/SQLiteSongDatabaseAccessor.java:847-854, 1334-1340`, `BJ/song/SongData.java:210`）。つまり選曲画面の総ノーツ数は「未定義の LN は 1」で、譜面が CN/HCN を指定していれば 2。

## 6. 譜面側の指定とプレイヤーの設定

### 6.1 種類の決まり方

LN ごとに種類を持つ：0=未定義、1=LN、2=CN、3=HCN（`jbms:LongNote` の定数）。

| 入力 | 挙動 | 出典 |
|---|---|---|
| BMS `#LNMODE n` | n が 0〜3 ならそのまま譜面の既定値にする。範囲外・数字でないものは警告して無視 | `jbms:CommandWord.lambda$static$15@0-49` |
| BMS の LN（5x/6x チャンネル・`#LNOBJ`） | 各 LN の種類 = 譜面の `#LNMODE`（無ければ 0=未定義） | `jbms:Section.makeTimeLines@13-16`, `@1300-1362`, `jbms:Section.lambda$makeTimeLines$9@388-400` |
| BMS `#LNTYPE` | 読んでいない（`#LNTYPE` を扱うコマンドが無い）。LNTYPE 2 (MGQ) にも対応していない [?] | `jbms:CommandWord`（LNTYPE の定義が無い） |
| bmson `info.ln_type` | 1〜3 なら譜面の既定値にする。それ以外は 0 | `jbms:BMSONDecoder.decode@766-801` |
| bmson ノーツの `t` | 1〜3 ならその LN の種類にする。それ以外は `info.ln_type` の値 | `jbms:BMSONDecoder.decode@2734-2768` |

### 6.2 プレイヤーの設定との優先順位

- プレイヤーの設定 `lnmode`：0=LN、1=CN、2=HCN（`BJ/PlayerConfig.java:123, 992`）。読み込み時に譜面に渡す（`BJ/PlayerResource.java:161, 189`）。
- **種類が未定義（0）の LN にだけ**プレイヤーの設定が効く。種類が決まっている LN（`#LNMODE 1..3`、bmson の `ln_type` / `t`）は設定に関係なくその種類（`JM:235-236, 425-426, 496-499, 563-564, 601-603`）。
- 1 つの譜面の中で種類が混ざることもある（bmson の `t`）。判定はノーツごとに種類を見て分ける。

### 6.3 難易度表のコースの制約

- 制約 `ln` / `cn` / `hcn`（`BJ/CourseData.java:192-202`）。
- コースを選ぶと、**プレイヤーの設定 `lnmode` 自体を書き換える**（0/1/2。`BJ/select/MusicSelector.java:501-503`）。コースが終わっても戻さない [?]。
- 譜面が種類を決めている LN には効かない（§6.2 と同じ理屈。コード上そうなる）。

## 7. スコアの分け方

- スコア表の主キーは `(sha256, mode)`（`BJ/ScoreDatabaseAccessor.java:56-58`）。
- 単曲の `mode` は、**譜面に種類未定義の LN が 1 本でもあれば** プレイヤーの `lnmode`（0/1/2）、無ければ 0（`BJ/PlayDataAccessor.java:149-167, 196-205`）。
  - LN の無い譜面と、`#LNMODE` で種類を決めた譜面は、設定に関係なく 1 つのスコア（mode 0）。
  - 「種類未定義の LN があるか」は曲 DB に特徴フラグとして持つ（`BJ/song/SongData.java:188-192, 411-412`）。選曲画面のキャッシュも同じ規則（`BJ/select/ScoreDataCache.java:36`）。
- コースの `mode` = `(LN あり ? lnmode : 0) + 譜面変更 × 10 + ハイスピ × 100 + 判定 × 1000 + ゲージ × 10000`（`BJ/PlayDataAccessor.java:317, 371-375`）。
- リプレイも同じ `lnmode` の規則でファイルを分ける（`BJ/PlayDataAccessor.java:466-472`）。

BMjoy の仕様書も `(譜面ハッシュ, LNモード, 判定プロファイル)` で分ける方針（`仕様書:346-348`）。DB には `score.ln_mode` 列が既にあるが、書き込みも読み出しも 0 固定（`BMJ/db/song_db.cpp:42-48, 391, 506, 532-533`）。
