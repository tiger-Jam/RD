# ここまでのまとめと、仕様書の見直し（2026-10-19）

2026-10-18〜19 の会話・決めたこと・作ったものを振り返り、仕様書 v0.1 と実際のずれを洗い出したもの。

## 1. 決まった方針

| 方針 | 中身 |
|---|---|
| LR2 が基準 | 既定の挙動は LR2 と同じ。違う挙動は勝手に入れず、入れるときは指摘して確認を取る。LR2 の不具合はまねない |
| 仕様だけまねる | OpenLR2・beatoraja は挙動を確かめるために読むだけ。コードの表現は写さない。公開前に点検する |
| 画面の文字 | LR2・IIDX の名前や、「未対応」などの注釈を出さない。使えない項目は灰色にするだけ |
| LR2 が弱い所 | 選曲のソートと鍵盤数の絞り込みは beatoraja の項目と並び |
| 難易度表が中心 | 譜面の #DIFFICULTY はあてにしない。選曲は難易度表が中心。表の URL は同梱しない |
| ハイスピ | LR2 の例外。「クラシック」（LR2 と同じ）と「フローティング」（緑数字で持つ）の 2 つ。ギアチェンは「カバー追従」と「緑数字に戻す」 |
| MOD | 定義ファイルとスクリプトだけ（DLL は許さない）。中心は出力の監視・見た目・フォルダの作成。プレーに影響する MOD は公式の記録にしない。カスタムゲージ・ランプ・判定、GAS も MOD |
| 記録 | ランプは遊んでいるゲージだけで決める。裏で計算した他のゲージは記録に残すだけ |
| コースの 2P | 正規を強制するコースに限り、2P 側はミラーを強制 |
| ノースピ段位 | コースの制約として持つ（ハイスピ固定などを LR2 準拠で） |
| 画面の既定 | 起動はウインドウ。そのあとは最後に使った状態。SD スキンは 2 倍 |
| F キー | LR2 に合わせる。BMjoy だけのショートカット（リザルトの F5、プレー中の F4）は残す。割り当てはいずれキーコンフィグで変えられるようにしたい |
| 選曲の数字 | ノーツ数・BPM は BMjoy の数え方（LR2 の数え方はまねない） |
| 定義されていない STOP | LR2 の不具合はまねない |
| LR2 からの引き継ぎ | 曲・記録・ゴースト・スキンのカスタマイズと位置の調整・カスタムフォルダの置き場まで。お気に入りなどには広げない |
| 遅くして遊んだ記録 | ふだんの記録には回数だけ。中身は別の表（play_log）に残して画面には出さない。MOD から読めるように |
| 開発用の口 | BMJ_DEV を切った配る版では読まない（入力を作る口から不正に使われないように） |

## 2. 作ったもの

- **プレー**：判定（LR2 の幅、LN・CN・HCN）、全ゲージの裏計算と GAS、ランプ（PERFECT を含む 7 種）、コース・段位（引き継ぎ・制約）、ハイスピの 2 つのモード・LIFT・緑数字、配置のオプション（5 鍵は 1〜5 鍵の中）、AUTO ADJUST、ゴーストとターゲット、リプレイ、全プレーの入力の記録、スキンの位置の調整
- **譜面**：BMS（LR2 と同じ読み方・乱数）、bmson、osu!mania（7K・8K）、FLAC、キー音と画像の探し方
- **スキン**：LR2 のプレイ・リザルト・コースリザルト・選曲・決定・スキンセレクト・キーコンフィグのスキン、動画の BGA と動画の画像、カスタマイズ
- **選曲**：LR2 と同じ一覧の作り方、難易度表、カスタムフォルダ（.lr2folder）、NEW SONG、お気に入り／IGNORE、フォルダランプ、タグエディター、検索、F キー、フォルダの監視
- **音**：音量（MASTER・KEY・BGM）、EQ、エフェクタ、ピッチ、サウンドセット
- **入力**：キーボード、パッド（台ごとに区別）、Windows の Raw Input、アナログ皿、MIDI
- **そのほか**：設定アプリ（LR2 の SETUP と同じ画面）、LR2 からの引き継ぎ、スクリーンショット、FPS 表示
- **速さ**：起動の確かめは 7 万譜面で数秒。全部の読み直しは 5 分 36 秒（LR2 は約 4 時間）

### 5.3 考え直したい論点

1. **GAS の置き場**：仕様書の 6章（本体の機能）と 14章（MOD）が食い違っている。
   - 案 A：GAS は本体の標準機能にして、設定で切り替える（6章に寄せる）。プレーには影響しない（全ゲージは裏でいつも計算している）ので、記録の扱いは変わらない。
   - 案 B：MOD の仕組みを作ってから、同梱の MOD として出す（14章に寄せる）。
   - 中身が同じで、記録にも影響しないなら、A が素直だと思う。MOD の仕組みは、カスタムゲージ（EX-HARD など）のように「本体に無いもの」を足すためにとっておく。
2. **新しい選曲画面（7段階目）は要るか**：LR2 の選曲スキンがそのまま使えて、カスタムフォルダも動く。新しい選曲スキンの形式（JSON か Lua か）を作るより先に、仮想フォルダの中身（自動で作るフォルダ、配置の保存の画面）を LR2 のスキンの上で動かすほうが、早く役に立つかもしれない。
3. **1 回ごとのプレーの記録（play の表）**：今は入力の記録がファイルで残るだけで、全ゲージの推移や判定のずれの統計は残していない。MOD（出力の監視・評価）とリコメンドの土台になるので、次に作る候補。
4. **判定プロファイルと F/S の統計**：カスタム判定は MOD で作る方針になったので、本体には「標準の判定」と「入力の記録から別の判定で計算し直す仕組み」だけを置けばいい。F/S の平均と標準偏差、補正の提案は本体に置くか、MOD に回すか。
5. **排他フルスクリーン**：LR2 は排他。今はボーダーレスだけ。入力の遅れが気になるなら排他も選べるようにする。
6. **コンテンツ取得・ARENA・リコメンド**（8〜11段階）：仕様書を作った時点の案。始めるときに、要るかどうかも含めて改めて決める。
